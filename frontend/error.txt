## STEP A1 — Create Database Tables in Neon

Go to Neon MCP (mcp__neon__run_sql) and run in order:

1. doctors table
2. doctor_schedules table
3. doctor_unavailability table
4. hospital_holidays table
5. appointment_slots table          ← has label column for fixed slot names
6. appointments table               ← status includes 'rescheduled'
7. appointment_audit_logs table

### hospital_holidays table
```sql
CREATE TABLE hospital_holidays (
    id      SERIAL PRIMARY KEY,
    date    DATE NOT NULL UNIQUE,
    name    TEXT NOT NULL           -- 'Sankranti', 'Republic Day', 'Maintenance Day'
);
```
Slot generator checks this before generating slots — no slots created on holidays.

### appointment_slots table (FIXED 4 SLOTS MODEL)
```sql
CREATE TABLE appointment_slots (
    id          TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
    doctor_id   TEXT NOT NULL REFERENCES doctors(id),
    slot_date   DATE NOT NULL,
    slot_time   TIME NOT NULL,
    label       TEXT NOT NULL,     -- 'Morning 1' | 'Morning 2' | 'Evening 1' | 'Evening 2'
    status      TEXT NOT NULL DEFAULT 'available',  -- available | held | booked
    held_until  TIMESTAMPTZ,
    UNIQUE (doctor_id, slot_date, slot_time)
);
```

### appointments table
```sql
CREATE TABLE appointments (
    id                  TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
    patient_name        TEXT NOT NULL,
    patient_email       TEXT NOT NULL,
    patient_phone       TEXT NOT NULL,
    doctor_id           TEXT NOT NULL REFERENCES doctors(id),
    slot_id             TEXT REFERENCES appointment_slots(id),
    appointment_date    DATE NOT NULL,
    appointment_time    TIME NOT NULL,
    reason              TEXT,
    came_before         BOOLEAN DEFAULT FALSE,
    status              TEXT NOT NULL DEFAULT 'pending',
    -- status lifecycle: pending → confirmed → rescheduled | completed | cancelled | no_show
    confirmation_sent   BOOLEAN DEFAULT FALSE,
    created_at          TIMESTAMPTZ DEFAULT NOW()
);
```

### appointment_audit_logs table
```sql
CREATE TABLE appointment_audit_logs (
    id              SERIAL PRIMARY KEY,
    appointment_id  TEXT NOT NULL,
    action          TEXT NOT NULL,  -- created | rescheduled | cancelled | completed | no_show
    performed_by    TEXT,           -- patient email or admin username
    timestamp       TIMESTAMPTZ DEFAULT NOW(),
    metadata        JSONB           -- old/new slot, reason, etc.
);
```

Test: Run SELECT * FROM doctors; — should return empty table, no error.

## STEP A3 — Slot Generator Script (FIXED 4 SLOTS PER DAY)

Create: backend/scripts/generate_slots.py

Each working day gets exactly 4 fixed slots per doctor:
  Morning Slot 1: 09:00  (label = 'Morning 1')
  Morning Slot 2: 10:30  (label = 'Morning 2')
  Evening Slot 1: 14:00  (label = 'Evening 1')
  Evening Slot 2: 15:30  (label = 'Evening 2')

Logic:
  For each active doctor:
    For each date in next 30 days:
      Check doctor_schedules for that day_of_week
      Check doctor_unavailability for that date
      Check hospital_holidays for that date
      If available:
        INSERT INTO appointment_slots (doctor_id, slot_date, slot_time, label, status)
        VALUES
          (doctor_id, date, '09:00', 'Morning 1', 'available'),
          (doctor_id, date, '10:30', 'Morning 2', 'available'),
          (doctor_id, date, '14:00', 'Evening 1', 'available'),
          (doctor_id, date, '15:30', 'Evening 2', 'available')
        ON CONFLICT (doctor_id, slot_date, slot_time) DO NOTHING;

Run once manually: python scripts/generate_slots.py
Test: SELECT COUNT(*) FROM appointment_slots; — should be (doctors × working days × 4).

Note: For now, add to render.yaml build command (idempotent ON CONFLICT DO NOTHING).
Future: remove from build, use APScheduler or Render Cron Job instead.

## STEP A4b — Booking Conversation Agent (NEW)

Create: backend/app/agent/appointment_nodes/booking_conversation_agent.py

This node runs FIRST after form submit (patient_name, email, phone, doctor_id, date received).
Uses llm_flash. Conducts a 3-question guided conversation:

  Q1 — Slot selection:
    Fetch available slots for doctor_id + appointment_date from appointment_slots
    Present 4 pills: Morning 1 (09:00) | Morning 2 (10:30) | Evening 1 (14:00) | Evening 2 (15:30)
    Patient selects one → fills appointment_time + slot_label + slot_id in state
    conversation_stage: 0 → 1

  Q2 — Reason for visit:
    "What is the reason for your visit today?"
    Free text → fills reason in state
    conversation_stage: 1 → 2

  Q3 — Prior visit:
    "Have you visited Navajeevana Ortho Hospitals before? (Yes / No)"
    Boolean → fills came_before in state
    If True → load patient_history from AsyncPostgresStore (visit count, preferred doctor)
    conversation_stage: 2 → 3 → conversation_complete = True

After conversation_complete = True:
  Passes enriched state to booking_orchestrator → slot_validator → ...

Implementation note:
  The frontend renders this as a structured step-by-step widget (not freeform chat).
  Each question is a POST to /appointment/conversation/{session_id} with the answer.
  Backend returns next question + available options.
  On conversation_complete, frontend POSTs final state to /appointment/book.

## STEP A5 — No-LLM Agent Nodes

Create these files in backend/app/agent/appointment_nodes/:

### availability_checker.py
  SELECT from appointment_slots WHERE doctor_id + slot_date + slot_time
  AND (status='available' OR (status='held' AND held_until < NOW()))
  Returns: availability_result = "available" | "taken"

### slot_validator.py
  Rules (no DB, no LLM):
  - appointment_date not in past
  - appointment_date within 30 days from today
  - slot_time is one of the 4 fixed times (09:00, 10:30, 14:00, 15:30)
  - doctor exists and is active
  Returns: availability_result = "valid" | "invalid" + error_message

### slot_hold_agent.py
  UPDATE appointment_slots
  SET status='held', held_until=NOW() + INTERVAL '5 minutes'
  WHERE id = $slot_id AND status='available'
  Returns: hold_result = "held" | "failed"

### slot_reservation_agent.py
  UPDATE appointment_slots SET status='booked' WHERE id = $slot_id
  INSERT INTO appointments (all fields including came_before, status='pending')
  Returns: booking_result = "confirmed" + appointment_id

### notification_agent.py
  Send confirmation email via Resend (same pattern as /api/send-email in frontend)
  To: patient_email
  Subject: Appointment Confirmed — Dr. [Name] on [Date] at [Time]
  Body includes: slot label (e.g. "Morning 1 — 09:00 AM"), reason, came_before note
  UPDATE appointments SET status='confirmed', confirmation_sent=TRUE

## STEP A6 — LLM Agent Nodes

Create in backend/app/agent/appointment_nodes/:

### booking_orchestrator.py  ← NO LLM
  Pure Python node — validate all required fields present after conversation agent
  (doctor_id, date, time, patient_email, reason, came_before must all be set)
  Loads patient history from AsyncPostgresStore if not already loaded
  Passes state to slot_validator

### alternative_suggester.py
  llm_flash
  If slot is taken: SELECT next available slots from remaining 3 fixed slots for same day
  Or same 4 slots on next working day
  Use LLM to format friendly message: "That slot is taken. Here are alternatives: ..."
  Returns: alternative_slots list + reply_message

### error_packager.py
  llm_flash
  If invalid_request: format friendly error message for patient
  Returns: reply_message

### memory_updater.py
  No LLM — AsyncPostgresStore write
  After confirmed booking:
  store.aput(("patient", patient_email), "appointment_history", {
    "last_appointment": date + time,
    "preferred_doctor": doctor_id,
    "came_before": came_before,
    "visit_count": incremented
  })

## STEP A7 — Wire Appointment Graph

Create: backend/app/agent/appointment_graph.py

Graph flow (UPDATED — conversation agent first):
  START → booking_conversation_agent   (llm_flash: slot + reason + came_before)
        → booking_orchestrator         (pure Python: validate all fields)
        → slot_validator               (rules check — no LLM)
        → availability_checker         (DB query — no LLM)
        → conditional:
              "available" → slot_hold_agent
              "taken"     → alternative_suggester → END
              "invalid"   → error_packager → END
        → slot_hold_agent → conditional:
              "held"   → slot_reservation_agent
              "failed" → alternative_suggester → END
        → slot_reservation_agent       (INSERT appointments, status='pending')
        → notification_agent           (send email → status='confirmed')
        → audit_logger                 (INSERT appointment_audit_logs, action='created')
        → memory_updater               (write to AsyncPostgresStore)
        → END

Test: Run the graph locally with a mock AppointmentState dict.

## STEP A8 — Add Queries to queries.py

Add to: backend/app/database/queries.py

New functions:
  get_doctors()                                → SELECT * FROM doctors WHERE is_active=TRUE
  get_available_slots(doctor_id, date)         → SELECT from appointment_slots WHERE status='available'
                                                  Returns 4 fixed slots (those not yet booked/held)
  get_appointments_by_email(email)             → SELECT from appointments WHERE patient_email=$1
  get_appointment_by_id(appt_id)              → full appointment detail
  cancel_appointment(appt_id)                 → UPDATE status='cancelled', release slot
  reschedule_appointment(appt_id, new_slot_id) →
    UPDATE appointment_slots SET status='available' WHERE id=old_slot_id  -- release old
    Hold new slot → slot_hold_agent
    Book new slot → slot_reservation_agent
    UPDATE appointments SET status='rescheduled', slot_id=new_slot_id
    INSERT appointment_audit_logs (action='rescheduled', metadata={old_slot, new_slot})
