## Appointment Booking Graph (LangGraph StateGraph)

```
[Booking Conversation Agent]    ← FIRST NODE (llm_flash)
        │   Runs after form submit (name, email, phone, doctor_id, date received)
        │   Conducts 3-question guided widget (NOT freeform chat):
        │     Q1: Which slot? → fetches available slots, shows 4 labeled pills
        │                       Patient picks one → fills appointment_time + slot_label
        │     Q2: Reason for visit? → free text → fills reason
        │     Q3: Visited Navajeevana before? → Yes / No → fills came_before
        │                       If Yes → load patient_history from AsyncPostgresStore
        │   conversation_complete = True → pass enriched state forward
        │
        ├── [Booking Orchestrator]    ← pure Python, NO LLM
        │       Validates all fields present (doctor_id, date, time, reason, came_before)
        │       Loads patient history from AsyncPostgresStore if not already loaded
        │
        ├── [Slot Validator]
        │       → checks: not in past, within 30-day booking window
        │       → checks: slot_time is one of 4 fixed times (09:00, 10:30, 14:00, 15:30)
        │       → checks: doctor leave calendar (doctor_unavailability table)
        │       → deterministic rule-based (NO LLM)
        │
        ├── fan-out (parallel):
        │       [Doctor Lookup Agent]      → verify doctor exists, get specialization
        │       [Availability Checker]     → queries appointment_slots (status='available')
        │
        ├── fan-in → [Slot Hold Agent]    ← race condition prevention
        │               → UPDATE slot status = 'held' for 5 min
        │               → if hold fails → slot was taken → route to Alternative Suggester
        │
        ├── 3 routes from Slot Hold:
        │       ├── hold_success     → [Slot Reservation Agent] → [Notification Agent]
        │       ├── slot_taken       → [Alternative Suggester]  → back to frontend
        │       └── invalid_request  → [Error Packager]         → back to frontend
        │
        └── [Audit Logger] → [Memory Updater]
                → audit_logger: INSERT appointment_audit_logs (action='created')
                → memory_updater: writes appointment to long-term memory
```

## Agent Responsibilities

| Agent | LLM? | Role |
|---|---|---|
| Booking Conversation Agent | llm_flash | Guided 3-question widget: slot pick, reason, came_before (yes/no) |
| Booking Orchestrator | No (Python) | Validates all fields present after conversation agent; loads patient history if came_before |
| Doctor Lookup Agent | No (DB) | Validates doctor name/ID against doctors table |
| Patient Verifier | No (Store) | Reads AsyncPostgresStore for patient history (called by conversation agent if came_before=True) |
| Availability Checker | No (DB) | SELECT from appointment_slots WHERE status='available' — returns 4 fixed labeled slots |
| Slot Validator | No (rules) | Date/time rules (fixed 4 times only) + doctor leave calendar check |
| Slot Hold Agent | No (DB) | UPDATE slot to 'held' (5 min TTL) — prevents race conditions |
| Slot Reservation Agent | No (DB) | UPDATE slot to 'booked', INSERT appointments row (with came_before field) |
| Alternative Suggester | llm_flash | Suggests remaining open slots from the 4 fixed slots (same day or next working day) |
| Notification Agent | No (Resend) | Sends confirmation email to patient — includes slot label, reason, came_before context |
| Error Packager | llm_flash | Friendly error message back to patient |
| Audit Logger | No (DB) | INSERT appointment_audit_logs (action='created'/'rescheduled'/'cancelled') |
| Memory Updater | No (Store) | Updates long-term memory with new appointment + came_before + visit_count |

## Database Tables (Neon PostgreSQL)

### doctors
```sql
CREATE TABLE doctors (
    id              TEXT PRIMARY KEY,     -- e.g. "dr_ramesh_k"
    full_name       TEXT NOT NULL,
    specialization  TEXT,                 -- Orthopedic, Physiotherapy, etc.
    is_active       BOOLEAN DEFAULT TRUE
);
```

### doctor_schedules  ← replaces hardcoded working_hours in doctors table
```sql
CREATE TABLE doctor_schedules (
    id          SERIAL PRIMARY KEY,
    doctor_id   TEXT NOT NULL,            -- FK to doctors.id
    day_of_week TEXT NOT NULL,            -- 'Mon','Tue','Wed','Thu','Fri','Sat'
    start_time  TIME NOT NULL,            -- e.g. 09:00
    end_time    TIME NOT NULL,            -- e.g. 17:00
    location    TEXT                      -- 'OPD Block A', 'Surgery OT'
);
```

### doctor_unavailability  ← leave calendar
```sql
CREATE TABLE doctor_unavailability (
    id          SERIAL PRIMARY KEY,
    doctor_id   TEXT NOT NULL,
    date        DATE NOT NULL,
    reason      TEXT                      -- 'Vacation', 'Conference', 'Surgery Day'
);
```

### hospital_holidays
```sql
CREATE TABLE hospital_holidays (
    id      SERIAL PRIMARY KEY,
    date    DATE NOT NULL UNIQUE,
    name    TEXT NOT NULL                 -- 'Sankranti', 'Republic Day', 'Maintenance Day'
);
```
Slot generator checks this before generating slots — no slots on holidays.

### appointment_slots  ← FIXED 4 SLOTS MODEL (not dynamic generation)
```sql
CREATE TABLE appointment_slots (
    id          TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
    doctor_id   TEXT NOT NULL REFERENCES doctors(id),
    slot_date   DATE NOT NULL,
    slot_time   TIME NOT NULL,
    label       TEXT NOT NULL,           -- 'Morning 1' | 'Morning 2' | 'Evening 1' | 'Evening 2'
    status      TEXT DEFAULT 'available', -- available | held | booked | blocked
    held_until  TIMESTAMPTZ,              -- for 5-min hold TTL
    created_at  TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(doctor_id, slot_date, slot_time)
);
-- Fixed 4 slots per working day: 09:00 (Morning 1), 10:30 (Morning 2),
--                                 14:00 (Evening 1), 15:30 (Evening 2)
-- Held slots whose TTL expired are treated as available — no cron needed to release them.
```

### appointments
```sql
CREATE TABLE appointments (
    id                  TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
    slot_id             TEXT REFERENCES appointment_slots(id),
    patient_email       TEXT NOT NULL,              -- = customer_id in memory store
    patient_name        TEXT NOT NULL,
    patient_phone       TEXT NOT NULL,
    doctor_id           TEXT NOT NULL REFERENCES doctors(id),
    appointment_date    DATE NOT NULL,
    appointment_time    TIME NOT NULL,
    slot_label          TEXT,                       -- 'Morning 1' | 'Morning 2' | etc.
    reason              TEXT,                       -- collected by conversation agent Q2
    came_before         BOOLEAN DEFAULT FALSE,      -- collected by conversation agent Q3
    status              TEXT DEFAULT 'pending',
    -- lifecycle: pending → confirmed → rescheduled | completed | cancelled | no_show
    confirmation_sent   BOOLEAN DEFAULT FALSE,
    created_at          TIMESTAMPTZ DEFAULT NOW(),
    updated_at          TIMESTAMPTZ DEFAULT NOW()
);
```

### appointment_audit_logs
```sql
CREATE TABLE appointment_audit_logs (
    id              SERIAL PRIMARY KEY,
    appointment_id  TEXT NOT NULL,
    action          TEXT NOT NULL,  -- created | rescheduled | cancelled | completed | no_show
    performed_by    TEXT,           -- patient email or admin username
    timestamp       TIMESTAMPTZ DEFAULT NOW(),
    metadata        JSONB           -- old/new slot, reason, etc.
);
```


## Slot Availability Logic (Availability Checker)

```
Before showing slots:
  1. Check doctor_unavailability for that date → if found, no slots shown
  2. Check hospital_holidays for that date → if found, no slots shown
  3. SELECT slot_id, slot_time, label, status FROM appointment_slots
     WHERE doctor_id = $1 AND slot_date = $2
     ORDER BY slot_time
     -- Always returns up to 4 rows; status tells frontend which to gray out
     -- Held slots whose TTL expired are treated as available
```

## Frontend Booking Form UX (3 steps)

```
Step 1: Choose Doctor + Date
  Doctor dropdown (pre-filled if arriving from /doctors via ?doctor_id=xxx)
  Date picker — future dates only, grays out non-schedule + leave + holiday days
  On date select: fetch GET /appointment/slots/{doctorId}?date=...

Step 2: Your Details
  Name: pre-filled from Clerk useUser(), editable
  Email: locked readOnly from Clerk
  Phone: pre-filled from Clerk if available

Step 3: Agent Conversation Widget
  Renders 3 sequential questions (not freeform chat):

  Q1 — Which slot do you prefer?
       4 labeled pills (from slot availability response):
       [ Morning 1 — 09:00 ] [ Morning 2 — 10:30 ] [ Evening 1 — 14:00 ] [ Evening 2 — 15:30 ]
       Booked slots grayed out; patient picks one available slot

  Q2 — Reason for visit
       "What is the reason for your visit today?" — textarea, required

  Q3 — Prior visit
       "Have you visited Navajeevana Ortho Hospitals before?"
       [ Yes ] [ No ] toggle buttons

  → [ Confirm Booking ] button appears after Q3 answered
  → slot is HELD for 5 min from this point (POST /appointment/conversation to complete)
  → POST /appointment/book with full state
```

## Key Constraints

- Slot availability = DB query only, never LLM decision
- Agent conversation = structured widget (not freeform chat) — Q1/Q2/Q3 in sequence
- came_before collected by agent Q3 → stored in appointments table + long-term memory
- Scheduling is deterministic — no hallucinated availability
- Fixed 4 slots per day (not dynamic) — Morning 1/2 + Evening 1/2
- Race conditions prevented by 5-min slot hold before confirmation
- Doctor schedule table + holiday table checked before generating slots
- Doctor leave calendar checked before showing slots
- Shared AsyncPostgresStore — appointment graph and ticket graph share patient memory
- Appointment graph is fully independent — ticketing graph unchanged
- Same Render project, same Vercel project — no new services
