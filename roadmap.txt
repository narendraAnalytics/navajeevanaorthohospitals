ARCHITECTURE: 8-AGENT PARALLEL LANGGRAPH GRAPH
================================================================================

Fan-Out -> Fan-In Pattern (3x faster than sequential):

  [START]
     |
  [Orchestrator] -- reads patient long-term memory, sets urgency (English only; multilingual deferred)
     |
  +--+--+--+
  |        |        |
[Intent  [Safety  [RAG
Classi-  Checker] Retrie-   <-- 3 agents run SIMULTANEOUSLY (~1s each)
fier]            ver]
  |        |        |
  +--+--+--+
     |
[Confidence Evaluator] -- fan-in, decides: auto_reply OR web_search OR escalate
     |
  +--+--+--+
  |        |        |
[Reply  [Tavily  [Escalation   <-- only one runs per ticket
Writer] Search]  Packager]
           |
      [Reply Writer]  <-- uses Tavily web results
     |        |
  +--+--+
     |
[Memory Manager] -- writes short-term (per ticket) + long-term (per patient)
     |
  [Human Review Queue]  <-- HITL: AI never emails patients directly
     |
  +--+--+--+
  |        |        |
[Approve [Edit  [Assign to
& Send]  & Send] Senior
  |        |     Staff]
  +--+--+
     |
  [Send Email]
     |
  [END]

Routing logic:
  safety flags present                        ->  escalate    (medical safety, always wins)
  RAG score >= 0.80, no flags                 ->  auto_reply  (use KB answer)
  RAG score < 0.80, no flags                  ->  web_search  (Tavily fallback)
    Tavily web_result score >= 0.50           ->  web_reply   (use web answer)
    Tavily web_result score <  0.50 or empty  ->  escalate    (poor sources, human needed)

Sequential (old 5-node):  ~9 seconds per ticket
Parallel (8-agent + Tavily tool): ~3 seconds per ticket  (60% faster)

✅ PHASE 3 -- LANGGRAPH AGENTS  (Tasks 5-11)
================================================================================

[T5] Agent 1 -- Orchestrator  (llm_flash)
     - app/agent/nodes/orchestrator.py
     - Reads AsyncPostgresStore for this customer_id (long-term memory)
     - Detects urgency (keyword match: critical/high/medium/low)
     - Language: English only (multilingual support deferred to final phase)
     - Returns: patient_history, urgency -> injected into state for ALL downstream agents

[T6] Agent 2 -- Intent Classifier  (llm_flash)  [PARALLEL BRANCH 1]
     - app/agent/nodes/intent_classifier.py
     - Runs simultaneously with Safety Checker and RAG Retriever
     - Gemini/Groq prompt: classify into category, sub_category, intent, sentiment, keywords
     - Output categories: appointment / test_prep / report / insurance / billing / post_surgery / emergency / other
     - Writes to: state["classifications"] list

[T7] Agent 3 -- Medical Safety Checker  (keyword-based, no LLM)  [PARALLEL BRANCH 2]
     - app/agent/nodes/safety_checker.py
     - MOST CRITICAL NODE -- deterministic keyword matching (not LLM -- never hallucinates)
     - Hard escalation rules:
         Medication words  -> ESCALATE (insulin, warfarin, metformin, steroids, blood thinner...)
         Symptom words     -> ESCALATE (pain, swelling, fever, wound, discharge, bleeding...)
         Emergency words   -> CRITICAL (chest pain, can't breathe, severe, unconscious...)
         Report words      -> ESCALATE (X-ray, MRI, CT scan, report, scan result...)
     - Writes to: state["safety_flags"] list
     - Test suite: 10 escalation cases + 3 safe cases (TDD)

[T8] Agent 4 -- RAG Knowledge Retriever  (llm_flash)  [PARALLEL BRANCH 3]
     - app/agent/nodes/rag_retriever.py
     - Queries ChromaDB: top 2 results from each of 5 collections
     - llm_flash synthesizes top 3 docs into answer_draft
     - Writes to: state["rag_results"] list with similarity_score per result

[T9] Agent 5 -- Confidence Evaluator  (logic-based)  [FAN-IN]
     - app/agent/nodes/confidence_evaluator.py
     - Waits for ALL 3 parallel agents to complete (LangGraph handles automatically)
     - Decision logic (3 routes now):
         any safety_flag.escalation_required=True  ->  route='escalate'   (safety always wins)
         max RAG similarity_score >= 0.80           ->  route='auto_reply' (KB has good answer)
         RAG score < 0.80, no safety flags          ->  route='web_search' (try Tavily first)
     - Safety flag ALWAYS overrides RAG confidence -- medical safety is non-negotiable
     - Sets: confidence_score, route_decision, escalation_reason
     - app/agent/edges.py : route_decision() function for conditional edge (3 paths)

[T9.5] Tavily Search Tool  (TavilySearchResults -- not an agent, no LLM)
     - app/agent/nodes/tavily_search.py
     - Only runs when route_decision='web_search'
     - Uses langchain_community.tools.TavilySearchResults (TAVILY_API_KEY from env)
     - Searches web for patient query + "orthopedic" context
     - Sets: web_results = [{url, content, score}]
     - Quality gate (logic-based, no LLM):
         best web_result score >= 0.50  ->  route_decision = 'web_reply'  -> Reply Writer
         score < 0.50 or no results     ->  route_decision = 'escalate'   -> Escalation Packager
     - Poor web sources are escalated, not silently replied to

[T10] Agent 6 -- Reply Writer  (llm_flash)
     - app/agent/nodes/reply_writer.py
     - Runs when route_decision='auto_reply' (uses rag_results) OR 'web_search' (uses web_results)
     - Writes reply in English
     - Self-check: re-reads draft vs original question, revises if it doesn't answer
     - Sets: reply_text, final_status='auto_resolved'
     - Source label in reply: "From our records" (KB) vs "From web search" (Tavily)

[T11] Agent 7 -- Escalation Packager  (llm_pro)
     - app/agent/nodes/escalation_packager.py
     - Only runs when route_decision='escalate'
     - Builds full brief for human staff (they never see ticket cold):
         1. Issue summary (2 sentences, plain language)
         2. Patient history (from long-term memory)
         3. Safety flags triggered (with trigger words)
         4. Suggested action for human agent
         5. Tone note (patient sentiment)
         6. Urgency color: Green / Yellow / Red / Critical
     - Sets: escalation_brief, final_status='escalated'

PHASE 4 -- GRAPH WIRING + MEMORY  (Tasks 12-13)
================================================================================

[T12] Agent 8 -- Memory Manager + Graph Compile
     - app/agent/nodes/memory_manager.py
       * llm_lite extracts patient facts from ticket (conditions, medications)
       * Writes short-term memory: PostgresSaver (per ticket thread_id)
       * Writes long-term memory: AsyncPostgresStore (per customer_id, persists forever)
       * Always runs last, regardless of auto_reply or escalate path

     - Install memory + Tavily packages:
       uv add langgraph-checkpoint-postgres langgraph-store-postgres langchain-community

     - app/agent/graph.py : wire 8 agent nodes + Tavily search tool
       graph.add_edge(START, "orchestrator")
       graph.add_edge("orchestrator", "intent_classifier")    # fan-out
       graph.add_edge("orchestrator", "safety_checker")       # fan-out
       graph.add_edge("orchestrator", "rag_retriever")        # fan-out
       graph.add_edge("intent_classifier", "confidence_eval") # fan-in
       graph.add_edge("safety_checker",    "confidence_eval") # fan-in
       graph.add_edge("rag_retriever",     "confidence_eval") # fan-in
       graph.add_conditional_edges("confidence_eval", route_decision,
           {"auto_reply":  "reply_writer",
            "web_search":  "tavily_search",        # NEW
            "escalate":    "escalation_packager"})
       graph.add_conditional_edges("tavily_search", route_decision,
           {"web_reply": "reply_writer",          # good Tavily results
            "escalate":  "escalation_packager"})  # poor/no Tavily results
       graph.add_edge("reply_writer",        "memory_manager")
       graph.add_edge("escalation_packager", "memory_manager")
       graph.add_edge("memory_manager", END)
       app = graph.compile(checkpointer=PostgresSaver(conn), store=AsyncPostgresStore(conn))

PHASE 4.5 -- HUMAN-IN-THE-LOOP (HITL)  (Task 13.5)
================================================================================

[T13.5] HITL Review Layer

     Goal: AI never sends emails directly to patients.
     Every reply (auto_resolved or escalated) lands in a human review queue first.

     Staff Review Dashboard shows:
       * Patient Name + Email
       * Original Ticket text
       * AI Generated Reply (ai_draft)
       * Confidence Score
       * Safety Flags triggered (if any)
       * Escalation Brief (if route=escalate)

     Three actions available to staff:

     1. Approve & Send
        AI reply is correct -> staff clicks Approve -> email sent unchanged
        ticket status: pending_review -> approved -> emailed
        reply type: ai_draft -> final_sent_reply

     2. Edit & Send
        Staff modifies AI reply -> submits edited version -> email sent
        ticket status: pending_review -> approved -> emailed
        reply type: ai_draft -> edited_reply -> final_sent_reply

     3. Assign to Senior Staff
        Staff cannot resolve -> routes ticket to senior staff member
        ticket status: pending_review -> escalated
        No email sent; senior staff takes over

     Database: updated ticket statuses
       draft_generated -> pending_review -> approved -> emailed
                                        -> escalated -> resolved

     Database: reply types
       ai_draft | edited_reply | final_sent_reply

     New router: app/routers/review.py
       GET   /review/pending              -- tickets awaiting human review
       GET   /review/{ticket_id}          -- full ticket + AI draft details
       PATCH /review/{ticket_id}/approve  -- approve AI reply as-is
       PATCH /review/{ticket_id}/edit     -- submit staff-edited reply
       POST  /review/{ticket_id}/send-email -- send email after approval
       PATCH /review/{ticket_id}/assign   -- assign to senior staff

     Note: HITL is NOT Agent 9. It is a human workflow step that runs AFTER
     all 8 agents complete. The AI pipeline is unchanged.
